# ADR-002: UI Interaction Standards and Resilience

## Context
Production environments frequently experience UI changes (Attribute drift, layout swaps, unexpected pop-ups). Relying on default strict selectors generated by UiPath Studio leads to fragile automations and high maintenance overhead.

## Decision
All enterprise RPA processes must adhere to the following element identification hierarchy to ensure UI drift tolerance:

1. **Targeted Custom Attributes (Primary):** Developers must use `data-QA`, `id`, or other stable backend-generated attributes. 
2. **Wildcards & Fuzzy Matching (Secondary):** Use `*` to bypass dynamic parts of an attribute (e.g., session IDs).
3. **Anchor Base (Tertiary):** Use parent-child relationships when the target element lacks stable selectors but has a static adjacent label.
4. **Computer Vision / Image Recognition (Last Resort):** Only to be used in VDI/Citrix environments or when DOM access is restricted. Avoid due to font-rendering sensitivity.

## Consequences
- **Positive:** Automations will survive minor UI updates without requiring code changes. False-positive clicks (T5 failures) will be minimized.
- **Negative:** Initial development time may increase as developers must manually inspect the DOM and potentially negotiate with frontend teams for `data-QA` attribute injection.
